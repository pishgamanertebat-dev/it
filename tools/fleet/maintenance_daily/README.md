# Daily maintenance report

The canonical `maintenance_daily_report` job runs daily at 12:00 Asia/Tehran through the existing minute-based scheduler. Its target is the previous Tehran calendar day of the actual due occurrence, using `overflow_report_date`. YAML parameters must be empty. The handler never chooses a latest available date. No records or no eligible recipients causes a logged skip with no document upload.

`report.py` opens only `E:\Function\تعمیرات 1405.xlsx`, through the existing exact-file `ScopedReader`. Its Windows file handle shares READ only and pins parent paths; active writers, reparse points and unsafe snapshots fail closed. Bytes are parsed in memory and hashed before/after. The source is never saved or exported by Excel. ZIP, worksheet dimensions, date strings and cell lengths have explicit bounds.

`layout.json` records the actual 56-sheet inspection. It includes 54 equipment templates and explicitly excludes `متفرقه` (mixed workshop activities) and `تعمیرگاه` (workshop history). Hidden equipment rows are retained. Headers occur on rows 2/3 and start at A or B. Source headers remain guarded exactly, while PDF columns use one fixed order: date, mechanism code, mechanic/repairer name, repair description, consumed parts. The per-sheet source coordinates are explicit in the inspected manifest. Sheet 705 has a stale title 409; the inspected sheet identity 705 is used and the original title is shown as a source discrepancy. S1/S2 use their actual sheet identities. The user-confirmed B/C header errors on 802 and 705 are corrected with explicit source-coordinate mappings, without changing any source cell. All other sheets map exact header aliases to the same report order. No runtime cell classification, code/name inference or value replacement is performed.

Every real activity inspected has its own Jalali string date. There are no real vertical date merges or proven unmerged continuation blocks. Blank dates never inherit a previous date. The explicitly inspected, isolated `.` placeholder on sheet 701 is skipped. Unproven undated activities fail closed. Generic bounded date merges are supported only when an inspected manifest explicitly enables them; production currently enables none. Exact duplicate rows remain duplicate source records. Only exact repeated headers are skipped. Changed headers, data-cell merges, formulas/errors and nonempty extra columns fail with the affected sheet identified.

New numeric or letter-plus-numeric equipment sheets are discovered in workbook order. Their header row and coordinates must match exactly one distinct inspected equipment shape. The existing parser then validates every record using the semantic header mapping, without inheriting legacy B/C corrections, placeholder exemptions or merge allowances. Every activity on a newly discovered sheet must have an explicit mechanism code matching its sheet identity. New names never need manual registration in `layout.json`. Unknown helper sheets are not silently excluded; ambiguous structures stop generation before any upload.

Sheet name, source title and record mechanism code are checked independently. A copied or changed title produces a structured `device_title_mismatch` warning and a PDF identity note, while grouping uses the inspected device identity or the verified new sheet code. No Excel cell is rewritten. All target-date mechanism conflicts, including blank or non-code cells, stop generation with the sheet, row, column, value and date. Existing non-target historical conflicts are logged and never reassigned to the target report. Missing inspected sheets are explicitly logged as `missing_inspected_sheet`; the existing contract has no mandatory-presence requirement. Diagnostics also accompany the scan result in `validation_warnings`, `discovered_sheets` and `missing_inspected_sheets`.

The renderer emits one combined A4 document, using local Windows Tahoma fonts, explicit column widths, repeated company/date/summary headers, device sections and table headers across pages. Rows stay intact. Text remains vector/searchable; generated font ToUnicode maps normalize Arabic contextual glyphs to searchable Persian Unicode without changing drawn glyphs. Every nonempty source field must be found in extracted PDF text, and all pages must render successfully. No raster images, scaling, text truncation, malformed/empty PDF or oversized upload is accepted. An individually overlong row fails rather than dropping data. Output replacement is atomic.

`delivery.py` resolves `reports.maintenance.daily_receive` through `AuthorizationStore.resolve_active_recipients`: active, approved private Bale users, deduplicated. It rechecks before generation and after sender initialization/source-version validation immediately before each upload. One PDF generation serves all still-authorized recipients. Individual upload failures are recorded independently; uncertain results are never retried automatically. Temporary generation files are removed, with cleanup logged. The existing `(schedule_id, due)` ledger deduplicates dispatch, including failed/uncertain occurrences.

`tools.authorization.maintenance` defines only `maintenance_daily_report_recipient` -> `reports.maintenance.daily_receive`, scoped to `reports.maintenance.daily`. The role has no profile mapping, Function resource or read/write/tool permission. The additive, integrity-checked, backed-up migration is idempotent and rejects extra grants/conflicting mappings/resources. Current production assignments are managed by the operator deployment script, never by the scheduled handler.

`integrations.hermes.deploy_maintenance_daily` performs prepare/assign/activate with candidate DB checks, actual native profile resolution, exact authorization deltas, source/protected-file hashes, original recipient sets, unchanged existing jobs and unchanged Gateway identity. It never restarts/reloads/updates Hermes or changes Windows Tasks. The live registry's volatile `updated_at` is separately recorded; all identity, private chat, approval and other fields remain guarded.
