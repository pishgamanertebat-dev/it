# ADMIN-1

Identity, organizational role, resource capability and expert profile are independent. `business_admin` grants only `function.read_all`. `business_admin` routes to the existing Admin profile at priority 10; specialized `office_supervisor -> admin` and `mechanical_staff -> maintenance` mappings retain priority 100. The existing resolver selects the highest priority and fails closed on an ambiguous top priority. Routing uses the additive `auth_role_profiles` extension; it grants no capability. Maintenance users do not lose their expert profile when given business read permission.

Canonical profile policy: `SOUL.md`, `config.template.yaml`. Runtime config is materialized from this policy with the existing inference model and public research backends; credentials are runtime-only. Native fresh-profile creation is used, without cloning Maintenance, conversations, memory, identity, pairing or refreshable OAuth grants. Shared bot transport remains owned by Default.

Public surface: `web_search`, `web_extract`, 17 `public_browser_*` operations, `skills_list`, `skill_view`, `delegate_task`. No terminal, PowerShell, CMD, process management, generic filesystem, code execution, patch, skill management or generic MCP. Delegation retains the Phase 1 parent ceiling and public network enforcement.

Business data: canonical `komatso-function-domain` plugin and `function_domain` worker. Operations are `function_list`, `function_search`, `function_metadata`, `function_read`, `function_attach`, `function_report`. The same plugin is permitted in Admin and Maintenance; the generic capability toolset resolver adds it only to approved private identities holding `function.read_all`. Native automatic plugin toolset inclusion is suppressed. Backend authorization is checked before work and again before publishing results; profile names never grant permission.

The resource root is fixed to `E:\Function`. Agent inputs are relative. Every component is opened using read-only Windows handles with OPEN_REPARSE_POINT; all reparse points are denied. Ancestor handles deny delete sharing, preventing rename/junction replacement. File handles deny writer/deleter sharing. Final handle paths and canonical paths are verified inside the fixed root. Traversal, drive paths, UNC, URIs, alternate streams and device aliases are unavailable. No executable, formula or macro is executed. Output/cache writes are limited to generated artifacts outside the operational root.

Paged extraction supports XLSX/XLSM, XLS via xlrd, XLSB via pyxlsb, PDF via the existing PyMuPDF, CSV/TSV, text-like files, DOCX/ODT via defused XML. Unknown binaries provide metadata and existing-file attachment. Parsing is limited to 64 MiB, attachments to 45 MiB and worker execution to 90 seconds; all current business files fit these limits. Compressed document expansion is bounded. Locked/unavailable sources fail clearly. Filename enumeration covers the entire resource tree, not an allowlist.

`function_report` accepts an exact Jalali date for driver mechanical/metalwork images or existing overflow rendering. The driver renderer uses the date in the sheet header, never sheet order/latest-date fallback. Duplicate matching dates or ambiguous/missing section headers fail instead of guessing. A missing day renders two dated stale notices; an empty section states that no defect was recorded for that date. Mechanical and metalwork content are isolated in two legible images. A memory-only renderer is available for an explicitly requested operator test delivery.

The 10:00 Asia/Tehran driver job reuses the existing scheduler, previous-day date calculation, recipient invariant and Bale document sender. It requires exactly one active office_supervisor, approved private registration and `reports.driver_daily.daily_receive`. Zero or multiple holders skip with clear logs; recipient/permission are checked again after rendering and before each upload. business_admin does not receive push permission. There is no LLM, no workbook modification and no latest-sheet fallback. The scheduled output is two searchable PDFs, one mechanical and one metalwork. Nonempty sections reuse the established native Excel exporter on one private, read-only snapshot, preserving workbook print layout and selecting only the exact dated sheet and four section columns. Macros/events/link updates are disabled. Missing dates and empty sections receive vector PDF notices. Temporary workbook/PDF files are removed after delivery. The 09:00 overflow job remains intact. Both legacy 08:00 repairs/metalwork pushes are disabled by operator request; they cannot send independently of the role-based 10:00 job.

The generic core patch adds configured profile and capability toolset resolvers plus optional exclusive attachment roots. It also fixes the observed native hot-profile reconcile deadlock: status self-RPC is moved off the serving event loop and the current host PID is not treated as a foreign standalone gateway. This fix is required before retrying hot discovery. None of these changes belong in Shared Fast Core; that core remains unchanged and supplies Operation/register_operations to the domain adapter.

Deployment is split from activation. `deploy_admin1.py` prepares/publishes profile/plugin files and uses official reload/rescan. `activate_admin1.py` verifies reviewed hashes, creates immediate backups, applies additive migration/assignments and the generic core/config payload only after explicit operator approval; it does not restart Gateway. Native Gateway start/restart is a separate approved operation. The driver schedule was enabled after explicit operator approval; runtime changes are picked up by the existing scheduler at each tick. No Hermes update, launcher modification, main Scheduled Task modification or Work Order DB mutation occurs.
